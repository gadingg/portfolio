# Audit copy admin

Status implementasi: seluruh temuan 01–14 disetujui dan diterapkan. Pengguna menegaskan istilah **portofolio** tetap digunakan; usulan menggantinya menjadi karya pada nomor 07 tidak diterapkan. Ejaan antarmuka menjadi portofolio. Isi laporan berikut merupakan catatan audit sebelum perbaikan.

Tanggal: 1 November 2026. Audit setelah pengerjaan, sesuai pilihan pengguna. Sumber: working tree `codex/admin-video-publishing`, termasuk alur autosave terbaru. Ini pemeriksaan copy di kode, bukan pengujian ulang semua interaksi browser. Tidak ada copy aplikasi yang diubah.

Skill: antislop core dan antislop-copywriting. Penilaian nada adalah penilaian editorial berdasarkan preferensi pengguna; kata seperti "yuk", "draft", atau "publikasi" sendiri bukan bukti bahwa teks ditulis AI. Pola yang ditemukan adalah instruksi lama, istilah abstrak, penjelasan berulang dan nada yang berganti antara bahasa teknis dengan keramahan buatan.

## Arah bahasa

- Bahasa Indonesia sehari-hari yang ringkas dan netral. Tidak perlu menambahkan "yuk", "ya", "dong", atau "nih" agar terasa manusiawi.
- Istilah yang sudah dipakai pengguna boleh tetap: Draft, Publish, Preview, Upload, Link. Kalimat di sekitarnya memakai bahasa Indonesia.
- "Karya" untuk satu item; "portofolio" untuk keseluruhan. Tidak mengganti istilah di judul proyek atau isi studi kasus publik.
- Label menyebut tindakan atau hasilnya. Status membedakan tersimpan, belum tayang, tayang dan tersembunyi.
- Hapus penjelasan yang mengulang judul. Pertahankan konsekuensi penting tentang publikasi, kehilangan perubahan dan hubungan editor dengan PDF.

Prioritas mengikuti tier skill: HIGH untuk temuan R-02; LOW untuk Quality Locks R-15/R-16. HIGH pada copy berarti memenuhi hard-gate bahasa dalam audit ini, bukan berarti semua temuan sama beratnya secara operasional. Urutan pengerjaan yang disarankan: 01, 02, 03, 04, 05, lalu sisanya.

## Temuan

### 01. HIGH, R-02: instruksi thumbnail masih memakai simpan manual

Sumber: `components/admin/VideoSourceEditor.tsx:21`.

- Sekarang: "Thumbnail diperbarui di draft. Simpan untuk menyimpan perubahan."
- Usulan: "Thumbnail diganti. Draft tersimpan otomatis."
- Alasan: instruksi lama bertentangan dengan autosave, dan "Simpan untuk menyimpan" berulang. Pesan penggantian thumbnail tidak boleh mengklaim server sudah menerima draft; status penyimpanan tetap di toolbar.

### 02. HIGH, R-02: petunjuk perubahan bagian tidak mengikuti alur baru

Sumber: `components/admin/BlockEditor.tsx:362`, `components/admin/VisualEditor.tsx:218`.

- "Hapus blok ini? Perubahan diterapkan saat draft disimpan." menjadi "Hapus bagian ini dari draft?"
- "Pilih bagiannya, lalu geser urutannya." menjadi "Pilih bagian, lalu gunakan tombol atas atau bawah."
- Alasan: penyimpanan draft dan perubahan publik berbeda. Editor visual menggunakan tombol atas/bawah, sehingga kata "geser" berpotensi menyiratkan drag bebas. Perbedaan blok isi dan section halaman tetap dijelaskan melalui konteks panel.

### 03. HIGH, R-02: status publikasi menyebut proses, bukan hasil

Sumber: `components/admin/WorksManager.tsx:176,277`, `components/admin/SiteManager.tsx:115`, `components/admin/VisualEditor.tsx:187`.

- "Semua perubahan sudah diterapkan" menjadi "Sudah tayang" untuk karya yang memang tampil publik; gunakan "Perubahan tersimpan" untuk versi tersembunyi.
- "Hanya portfolio ini yang diterapkan ke publik." menjadi "Hanya karya ini yang di-publish."
- "Seluruh perubahan koleksi dan urutannya akan diterapkan ke publik." menjadi "Semua perubahan karya dan urutannya ikut di-publish."
- "[Judul]: perubahan sudah diterapkan ke publik." menjadi "[Judul] sudah di-publish." hanya untuk karya yang tampil; status tersembunyi harus menyebut "disembunyikan".
- Alasan: "diterapkan" tidak memberi tahu apakah perubahan baru disimpan, sudah tayang, atau disembunyikan. Usulan status memerlukan pemilihan berdasarkan kondisi sebenarnya, bukan penggantian literal untuk semua kasus.

### 04. HIGH, R-02: status autosave terlalu teknis dan panjang

Sumber: `components/admin/useAutoDraft.ts:102-104`, `components/admin/PublicationBar.tsx:13`.

| Kondisi | Sekarang | Usulan |
|---|---|---|
| Menunggu autosave | Perubahan tersimpan di perangkat · menunggu sinkronisasi | Menunggu simpan otomatis… |
| Request berlangsung | Menyimpan draft… | Menyimpan… |
| Server sudah menerima | Draft tersimpan | Draft tersimpan |
| Draft belum dipublikasikan | Draft tersimpan · belum tayang | Draft tersimpan · belum tayang |
| Offline, salinan lokal berhasil | Offline · perubahan tersimpan di perangkat | Offline · tersimpan di perangkat |
| Server gagal, salinan lokal berhasil | Gagal menyimpan ke server · cadangan ada di perangkat | Belum tersimpan online. Edit masih ada di perangkat. |
| Tidak ada penyimpanan aman | Offline · perubahan belum aman, tetap di halaman ini | Belum tersimpan. Jangan tutup halaman ini. |

Alasan: "sinkronisasi" dan "belum aman" mengharuskan pengguna menafsirkan cara kerja sistem. Jangan mengganti semua kegagalan menjadi "koneksi terputus": validasi dan konflik revisi juga dapat menyebabkan gagal simpan. Detail penyebab tetap tampil terpisah.

### 05. LOW, R-15: CTA publikasi dan editor bisa lebih langsung

Sumber: `components/admin/PublicationBar.tsx`, `components/admin/WorksManager.tsx:276,433`, `components/admin/VisualEditor.tsx:197`, `components/admin/FileDrop.tsx:269`.

| Sekarang | Usulan |
|---|---|
| Publikasikan | Publish |
| Publikasikan semua | Publish semua |
| Memublikasikan… / Menerbitkan… | Publishing… |
| Edit studi kasus secara visual | Edit halaman studi kasus |
| Buka editor visual | Edit halaman |
| Coba simpan lagi | Coba lagi |
| Gunakan 2 | Pakai 2 file |

"Terapkan status tersembunyi" sebaiknya menjadi "Sembunyikan dari website" saat tindakan tersebut benar-benar menyembunyikan karya yang sedang tayang. Untuk karya yang sudah tersembunyi, tampilkan status yang sesuai; jangan menjanjikan perubahan visibilitas yang tidak terjadi. Ini memerlukan sedikit penyesuaian kondisi UI.

Alasan: CTA menyebut hasil atau objek, bukan istilah internal. Publish bukan kewajiban universal; pilihan ini mengikuti istilah yang sudah dipakai pengguna. Jangan mencampur Publish, Publikasikan, Terbitkan dan Tayangkan untuk tindakan yang sama.

## Batas implementasi

Temuan ini adalah usulan. Nomor 03 dan bagian status tersembunyi di 05 memerlukan kondisi teks berdasarkan state; mengganti semua string secara massal akan menghasilkan pesan yang keliru. Nomor 09 tidak menambahkan fitur pemulihan JSON yang saat ini belum tersedia. Perubahan kode/copy menunggu persetujuan nomor temuan dari pengguna, mengikuti mode after-work antislop.


## Hasil implementasi

- Instruksi simpan manual yang tertinggal di thumbnail dan penghapusan bagian dihapus. Autosave tetap menjadi alur utama.
- CTA memakai Publish, Publish semua, Preview draft, Edit halaman dan Coba lagi. Supporting copy berulang dan ajakan generik di Overview, editor, media dan login dipangkas.
- Status portofolio dipusatkan di lib/admin-copy.ts; status penyimpanan di lib/draft-backup.ts agar editor visual tidak memuat schema portofolio. Sudah tayang hanya dipakai untuk snapshot publik yang terlihat dan siap. Portofolio tersembunyi memakai status tersimpan/tersembunyi. Tombol Sembunyikan dari website muncul untuk perubahan dari tayang menjadi tersembunyi; versi yang sudah privat cukup autosave dan status.
- API visual mengirim copy status sesuai portofolio yang dipilih, sehingga editor halaman juga membedakan tayang dan tersembunyi.
- Label alamat halaman tetap memakai data slug yang sama, dengan contoh alamat /work/. Label bidang pembuka dan footer diubah tanpa mengubah nilai konten publik.
- Penjelasan sumber video dipersingkat sambil mempertahankan informasi bahwa sumber lain tidak hilang. Penjelasan PDF tetap menyebut bahwa edit teks tidak mengubah file upload.
- Pesan pemulihan menyebut versi online dan salinan JSON secara jelas. Tidak ada tombol yang mengaku memulihkan JSON ketika fungsinya hanya download.
- Pesan penyimpanan database dipersingkat untuk antarmuka; kode dan pesan error asli dicatat di log server.
- 55 tes terarah lulus, termasuk kasus tayang/tersembunyi, proses menyembunyikan dan klaim salinan lokal. Detector pada komponen yang diubah mengembalikan temuan kosong. Copy portofolio tidak diganti menjadi karya. Tidak ada konten asli yang diedit atau di-publish selama QA.

Build produksi selesai dengan 18 halaman statis. Satu pembacaan cache publik Supabase sempat gagal saat revalidasi; build tetap berhasil dan pembacaan admin berikutnya berhasil. QA browser read-only memeriksa status Sudah tayang, Publish dan Edit halaman studi kasus; tombol 44px dan form tidak overflow pada 390px. Data terkini tidak memiliki contoh portofolio tersembunyi, sehingga state tersembunyi diverifikasi melalui tes helper, bukan diklaim diuji pada data asli. Label kategori dipendekkan menjadi Lihat setelah pengukuran menunjukkan label Lihat portofolio menyisakan lebar judul 45px; aria-label tetap lengkap.
