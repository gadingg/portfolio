# CMS reliability and Overview audit

Scope: Works CRUD, case-study activation/category changes, block operations, shared uploads, Site/CV editing, live editor selection/insertion/history/persistence, logout error reporting, public data projections, and new engagement collection/summary. This is scoped evidence, not a guarantee that every possible browser or concurrent workflow is bug-free.

## Confirmed defects and corrections

| Area | Finding | Correction |
| --- | --- | --- |
| Works | Unchecking the case-study option or changing category removed the complete study object. | Persistent private archive retains copy, blocks, slug and visual layout. Re-enabling restores it. Server also retains recovery data when an older client omits the study. |
| Privacy | A recovery copy in a published document could leak through public serialization/media authorization. | Public projection strips the archive; media reference traversal ignores archived content. |
| Navigation | Opening visual editing could abandon unsaved metadata. | Save-before-open action; failure keeps the user in the form. Other unsaved navigation has a CMS confirmation. |
| Async | Repeated save/upload actions could race React's busy update. | Immediate request locks supplement disabled controls. Editor compares the submitted layout with current content before clearing dirty state. |
| Site copy | Form edits of nested text generated by the visual editor could duplicate the old copy. | Replace text once while preserving direct icon children. |
| Deletion | Block/CV and Grapes toolbar deletion offered inconsistent protection. | Shared accessible CMS dialog, including Grapes command interception; Undo/Redo remains available. |
| Logout | Network/auth failures were presented as successful logout. | Server checks sign-out errors; client stays on page and reports failure. |
| Works usability | Long mixed form hid the main visual-edit action. | Searchable collections, clear visual-edit action, disclosed structured case settings, explicit archived-study state. |
| Live editor | Generic selection names and fully expanded layout properties made editing hard to scan. | Human-readable selection names, Indonesian property labels, collapsed layout/spacing groups and visible mobile action labels. |

## Analytics

Overview compares real public/editor inventory counts, with an explicit example count. Engagement has 7/30/90-day filters, daily bars, five action types, popular works and accessible tabular detail. Unavailable data differs from a valid zero.

Migration `006_engagement.sql` creates a private RLS-enabled event table and service-only recording/summary functions. No IP, identity, visitor ID, referrer, arbitrary URL, or user agent is stored. UUID event keys make duplicate submissions idempotent; a global database cap limits insertion volume. Client debounce suppresses rapid duplicate clicks. Examples, admin routes, admin preview, iframe previews, localhost, Do Not Track and Global Privacy Control are excluded. These counts are click/open events, not unique people, video playback completion, or Instagram-native engagement. Analytics can be blocked or disabled by browsers and is not a billing-grade measurement.

Live read checks: summary returned total 0 and seven daily rows; anonymous table reads and summary RPC both returned permission denied `42501`. No invented events were inserted. Recording endpoint success, validation/failure paths and collector exclusions are exercised with isolated mocks. The new tracker requires a new source deployment before production activity is recorded.
