# Visual CMS editor

The user approved a visual editor for homepage and case studies, with free arrangement of sections, columns, and layout in the manner of Elementor. Double-click text edits copy directly. Existing draft/publish separation remains binding. Antislop is after-mode, chosen explicitly for this task.

Mode: Operate. This is a precisely specified extension to the incumbent CMS; retain dark admin surfaces, amber actions, Lucide controls, and the public orange/Manrope identity. No new identity, raster assets, factual claims, or database migration is required.

Inherited operational dials: ENERGY 1 / RHYTHM 1 / MOTION 1. The canvas is the focal point; subdued admin controls serve editing and explicit publishing. Icons describe actual actions (undo, move, image, device) and continue the user's requested Lucide family.

THESIS: Put the actual page in the editing workspace so copy and layout changes are visible where they belong.
OWN-WORLD: Existing Gading operational admin shell around a public-style canvas; GrapesJS supplies native editing and nesting behavior, not a replacement visual identity.
STORY: Enter from Website or a case study, select an element, double-click text or adjust styles, insert/move sections and columns through the canvas/structure tree, save a private draft, then publish deliberately.
FIRST VIEWPORT: Page title and save state above the canvas; section/text/image blocks in a compact sidebar. Undo, redo, preview and device controls remain near the canvas.
FORM: Full-window protected editing workspace, resizable responsive canvas, shared upload/library, visible loading/error/conflict states, unsaved-navigation protection.

Persistence: optional sanitized HTML/CSS layout inside existing Site and Works documents. Existing content remains the default until a visual draft is saved and published. No browser localStorage persistence. A case-study publication updates only that selected work, preserving other unpublished Works drafts.

Security: authorized same-origin mutation APIs, revision checks, script/event/form/embed removal, CSS parsing and URL restrictions, private upload bucket. No arbitrary script or plugin execution is exposed to the administrator.

Verification: real browser editing and persisted reload, draft isolation, styles/columns, preview and device switching, upload/library flow, guards, sanitization, and production build. Preserve the user's original content following disposable QA changes.
