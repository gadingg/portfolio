# Portfolio homepage and public project presentation

Mode: Experience. Existing surface enhancement, using the incumbent dark/orange identity and the user's exact headline. Code-led refinement with existing assets and real application captures. No replacement visual identity or generated artwork.

## Direction contract

THESIS: The work leads. A compact introduction immediately opens into visual artifacts; project stories explain the problem, the response, and the impact. Remove the oversized resume interlude.

OWN-WORLD: Near-black canvas (#060706), warm white (#f3f0e8), orange (#ff5a1f). Broad, confident sans lettering, thin dividers, large unboxed artwork, compact rounded rectangular controls. Orange identifies the primary action and active state. Lucide icons communicate behavior alongside visible labels.

STORY: See the visual execution; understand the practical thinking; inspect a case study or app; contact Gading. Supporting about/capability/toolkit content follows the work.

FIRST VIEWPORT: A clear name and four destination links. “I think. I create. I solve.” in prominent sans lettering, with an Indonesian introduction and two distinct actions. An unequal-width strip of actual application captures and existing archive material begins within the first desktop viewport.

FORM: Refine the existing portfolio world, not a new visual-world selection. Work strip, alternating project features, visual archive, compact practical-tool index, then about and contact. On mobile, horizontal arrangements stack with complete labels and no hidden actions. ENERGY 2 / RHYTHM 3 / MOTION 2. One authored hover/focus image reveal in the work strip; no scroll locking or auto-playing carousel.

FINISH: Real CMS content and fallback states, keyboard operability, a usable gallery lightbox, valid destinations, no role/year metadata in the public showcase, and desktop/mobile browser evidence.

## Behavior and sources
- Case study links are named “View case study”; external app links “Open app”; gallery buttons “Enlarge image.”
- Public CMS data remains authoritative. Legacy stock project covers may use verified app screenshots; future custom CMS covers remain respected.
- Archive combines custom items from `/api/gallery` with two real Listing Hub captures, with loading, retry, image-error and keyboard dialog states. Unchanged setup seed illustrations are excluded from public presentation.
- Source facts come from the master brief. The three known project narratives use the supplied brief in the presentation layer and do not overwrite CMS records. Other project bodies continue to come from CMS content blocks; covers continue to respect custom uploaded artwork.
- Keep CV as a secondary direct link, away from the primary work action.
- Antislop is applied during implementation as the recommended default following “Go ahead”; no global preference is saved.
